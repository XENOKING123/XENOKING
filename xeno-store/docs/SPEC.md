# XENO STORE — Engineering Specification (v1.0)

XENO STORE is a native, on-console PS5 game store + download manager by XENOKING.
It is a brand-new tool that mixes the best of **BlackBox** (storefront + catalog
with verified Archive.org/Vikingfile releases), **Orbit Store** (TV-first Discover /
Browse / Library / Downloads, queue, phone pairing, source choice, storage choice)
and **Overdrive** (controller-grade spatial navigation, sheets, one-primary-action
pages, segmented transport with failover) — and goes further: a bigger auto-synced
catalog, faster segmented downloads, PKG auto-install, a speed/space planner,
collections, themes, 14 languages, phone companion, self-update, and more.

This document is the **contract** every part of the project follows. If code and
this spec disagree, fix one of them — never leave them apart.

---

## 0. Non-negotiables

1. **It runs on the console.** One ELF payload (`xeno-store.elf`) built with the
   ps5-payload-dev SDK. It serves the UI + JSON API on **TCP :9095** and keeps
   downloading while the PS5 browser is closed.
2. **Zero external dependencies on the console.** The UI and catalog are embedded in
   the ELF; cover art loads from the catalog's CDN URLs when online. Everything else
   is offline-capable.
3. **Memory safe C.** Every buffer is bounded, every path is validated, every Sony
   API symbol is resolved defensively (direct link only for libraries proven to load
   on every firmware; everything else via `dlopen`/`dlsym` with graceful fallback).
4. **No telemetry, no accounts.** Local network only. No external calls except the
   catalog/update sync the user can turn off.
5. **The browser UI is a single file** (`index.html` with inlined CSS/JS), written in
   plain ES2017 JavaScript (no `?.`, no `??`, no modules, no frameworks) because it
   runs inside the PS5's WebKit. It must also look great on a phone and a desktop.
6. **Fully usable with a DualSense**: D-pad/stick = move, ✕ = select, ○ = back,
   □ = favorite, △ = search, L1/R1 = tabs, Options = settings.

## 2. Build system (`xeno-store/Makefile`)

Targets (all run from `xeno-store/`):

| target | what |
|---|---|
| `make web` | `node web/build.mjs` → `web/dist/index.html` |
| `make catalog` | `python3 tools/catalog/build_catalog.py --offline` → `catalog/xeno-catalog.json` (+ `--validate`) |
| `make assets` | `python3 tools/gen_assets.py` → `src/assets.h` (needs web + catalog) |
| `make host` | host binary `build/host/xeno-store` with `cc` (gcc/clang). `-DXENO_HOST=1`. Links OpenSSL if `pkg-config --exists openssl`, else HTTP only. |
| `make test` | `make host` then `tests/host/run.sh` |
| `make ps5` | cross-compile `xeno-store.elf` and `xeno-store-browser.elf` (needs `PS5_PAYLOAD_SDK`) |

| `make all` | web catalog assets ps5 pkg |

Compiler flags: `-std=gnu11 -Wall -Wextra -Werror -O2 -fstack-protector-strong -D_FILE_OFFSET_BITS=64 -DXENO_VERSION=\"$(VERSION)\"`.

**Do NOT direct-link** `-lSceNet -lSceSsl -lSceHttp2` — resolve them at runtime (§4.2).
The browser variant adds `-DLAUNCH_BROWSER`.

## 3. Runtime model on the console

- Process: single ELF, no fork. Threads: 1 acceptor + N HTTP worker threads (pool of 8) +
  download workers (1 per active job, each job may run up to `connections` segment threads)
  + 1 housekeeping thread (persist, catalog refresh, keep-awake tick, retry timers).
- Ports: **9095** HTTP. If bind fails: toast "XENO STORE already running on :9095" and exit 0.
- Data dir: `/data/xeno-store/` (created on start). Files:
  - `settings.json`, `favorites.json`, `collections.json`, `queue.json`, `recent.json`
  - `catalog.json` (refreshed copy, only when newer revision than embedded) + `catalog.meta.json`
  - `log.txt` (rotated at 2 MiB → `log.1.txt`)
  - `xeno-store.elf` (self-update staging; `xeno-store.elf.new` → rename on verified)
- Storage roots (download destinations), discovered at start and on `/api/storage` call:
  `/data` (Internal), `/mnt/ext0`, `/mnt/ext1` (M.2), `/mnt/usb0` … `/mnt/usb7` (USB).
  A root is listed if it `stat`s as a directory and `statvfs` works; `writable` is tested
  by creating/removing `<root>/xeno-store/.wtest`. Internal is default.
- Destination layout under a root:
  - images (`exfat`, `ffpfsc`, `ffpkg`, `ffpfs`) → `<root>/homebrew/<filename>` (ShadowMountPlus scans `homebrew/`)
  - packages (`pkg`, `fpkg`) → `<root>/xeno-store/pkg/<filename>`
  - archives (`zip`, `rar`, `7z`) and anything else → `<root>/xeno-store/files/<filename>`
  - partial file: `<final>.xpart`; sidecar: `<final>.xpart.json` (both removed on completion)
- Host build: data dir `./xeno-data/` (or `--data DIR`), roots = `./xeno-data/downloads` plus any `--root PATH` args; port `--port N` (default 9095).

### 3.1 CLI / argv
`xeno-store [--port N] [--data DIR] [--root PATH]... [--no-browser] [--log-level debug|info|warn]`
(On PS5 the loader passes no args; defaults apply.)

### 3.2 Startup order
log → data dir → settings load → catalog load (embedded, then cached if newer) → storage scan →
queue load (jobs that were running become `paused` with message "Stopped when XENO STORE closed") →
server bind → housekeeping thread → (LAUNCH_BROWSER: open `http://127.0.0.1:9095/`) → toast
"XENO STORE ready · http://<ip>:9095" (ip from `getifaddrs`, first non-loopback IPv4).

## 4. C payload modules

### 4.1 server.c
- HTTP/1.1, `Connection: close` (simple, robust), max request line 4 KiB, max headers 16 KiB,
  max body 1 MiB (JSON APIs), read timeout 15 s, write via `send_all`.
- Methods: GET, POST, PUT, DELETE, OPTIONS (CORS preflight: `Access-Control-Allow-Origin: *`,
  `Access-Control-Allow-Methods: GET,POST,PUT,DELETE,OPTIONS`, `Access-Control-Allow-Headers: Content-Type`).
- Static routes: `/` and `/index.html` → embedded UI (`Content-Type: text/html; charset=utf-8`,
  `Cache-Control: no-cache`, ETag = build hash; serve gzip variant when `Accept-Encoding` has gzip).
  `/logo.jpg`, `/icon.png`, `/manifest.webmanifest` (PWA manifest so phones can "Add to home screen"),
  `/catalog.json` → current catalog (gzip if accepted, ETag = revision), `/i18n/<code>.json` (embedded).
- `/api/*` → api.c dispatcher with `(method, path, query, body)`; handlers write JSON via json.c.
- `/pkgsrv/<token>` → range-capable file serving of a staged .pkg (used by the DPI fallback install path, loopback only).
- Every response has `Content-Length`. Errors: JSON `{"ok":false,"error":"code","message":"human text"}` with proper status.
- Path/query parsing must reject `..`, NUL, control chars. Query values are URL-decoded.
- Rate/size guards: a request body over limit → 413; unknown route → 404 JSON.

### 4.2 http_client.h (transport)
```c
typedef struct xhttp_resp {
  int status;            // 0 on transport error
  int64_t content_length;// -1 unknown
  int64_t range_start, range_total; // from Content-Range, -1 if absent
  char etag[128]; char last_modified[64]; char location[1024];
  char content_type[96]; char filename[256]; // from Content-Disposition if any
  int retry_after;       // seconds, 0 if absent
  int accept_ranges;     // 1 if "bytes"
} xhttp_resp;
typedef struct xhttp_req {
  const char *method; const char *url; const char *user_agent;
  int64_t range_start, range_end;   // -1 = no Range header
  const char *extra_headers;        // "Name: v\r\n..." or NULL
  const char *body; size_t body_len;
  int connect_timeout_ms, recv_timeout_ms;
  int follow_redirects;             // max hops (0 = none)
  int insecure_tls;                 // only honored by backends that can
  volatile int *cancel_flag;        // checked between reads; non-zero = abort
} xhttp_req;
typedef struct xhttp_conn xhttp_conn;        // opaque, per request
int   xhttp_global_init(void);               // once; returns 0 or -1 (sets xhttp_last_error)
int   xhttp_open(const xhttp_req*, xhttp_conn**, xhttp_resp*); // sends request, parses headers
int   xhttp_read(xhttp_conn*, void *buf, size_t cap);          // >0 bytes, 0 EOF, <0 error
void  xhttp_close(xhttp_conn*);
const char *xhttp_last_error(void);          // thread-local string
int   xhttp_available(void);                 // 1 when the backend initialized (PS5: sprx loaded)
```
- **http_sce.c**: dlopen `libSceNet.sprx`, `libSceSsl.sprx`, `libSceHttp2.sprx` (also try
  `libSceHttp.sprx` as a second backend if Http2 is missing — same interface, v1 symbols).
  Init like the SDK `http2_get` sample: `sceNetInit`, `sceNetPoolCreate(name, 1<<20 (1 MiB), 0)`,
  `sceSslInit(512*1024)`, `sceHttp2Init(netMem, sslCtx, 1<<20, 32)` (32 = max concurrent),
  one template per thread-use with UA `XENO-STORE/<ver> (PlayStation 5)`.
  Request: `sceHttp2CreateRequestWithURL(tmpl, method, url, 0)`, add headers
  (`sceHttp2AddRequestHeader(id, name, value, 0)`; Range: `bytes=a-b`), set timeouts if
  `sceHttp2SetConnectTimeOut/SetRecvTimeOut/SetSendTimeOut` resolve, `sceHttp2SendRequest`,
  `sceHttp2GetStatusCode`, `sceHttp2GetAllResponseHeaders(id, &hdr, &len)` → parse,
  `sceHttp2ReadData` loop with 256 KiB buffers. Redirects: if `sceHttp2SetAutoRedirect` is
  absent, handle 301/302/303/307/308 manually up to `follow_redirects`. Cancel: set flag; the
  reader thread checks it and also calls `sceHttp2AbortRequest` if resolved.
  Symbols are looked up by name; every missing optional symbol is logged once and skipped.
  If the core set is missing, `xhttp_available()==0` and the UI shows "Downloads unavailable
  on this firmware" (catalog browsing still works).
- **http_posix.c**: `getaddrinfo` + `connect` (timeout via non-blocking + poll), hand-written
  HTTP/1.1 client (chunked encoding supported for sync/API fetches; downloads require
  Content-Length or EOF), TLS via OpenSSL when `XENO_HAVE_OPENSSL` (SNI, default verify;
  `insecure_tls` disables verify). Used by host build and tests.

## 5. Threading & safety rules (C)
- One global mutex per subsystem (`queue_mu`, `settings_mu`, `catalog_mu`, `log_mu`). Never hold two
  at once except `queue_mu` → `log_mu`.
- Segment threads write with `pwrite(fd, buf, n, offset)` to a preallocated file (`ftruncate` to total
  size when known; on PS5 FreeBSD this is sparse — fine).
- All string ops via `snprintf`/`strlcpy`-style helpers in util.c; no `strcpy/strcat/sprintf/gets`.
- Paths handed to the FS are built only by `storage_join(root, category, filename)` which:
  rejects empty names, `..`, `/`, `\`, NUL, control chars, leading `.`; truncates to 200 bytes;
  and ensures the root is one of the known roots.
- Any API that deletes files operates only on paths recorded in the job (never on client-supplied paths).
- `volatile int` flags + mutex for cross-thread state; no busy loops (use `nanosleep`/`pthread_cond`).

## 6. HTTP API (JSON, all under `/api`)

Common envelope: success → the documented object (always includes `"ok":true`); failure →
`{"ok":false,"error":"<code>","message":"<text>"}`. Timestamps are Unix seconds. Sizes in bytes.

### 6.1 System
- `GET /api/status` →
  `{ok, app:"XENO STORE", version, build, platform:"ps5"|"host", fw:"13.60", ip:"192.168.1.20", port:9095,
    uptime:123, downloadsAvailable:bool, catalog:{revision, games, releases, source:"embedded"|"cached", updatedAt},
    queue:{active, queued, paused, failed, done, speed, remaining}, storage:[...§6.4 summary...],
    update:{available:bool, latest:"1.0.1", current:"1.0.0", notes:""}, notices:[{id, text}]}`
- `GET /api/log?lines=N` → `{ok, lines:[...]}`
- `POST /api/system/toast {text}` → `{ok}` (debug)
- `POST /api/system/stop` → saves queue, toasts, exits (for self-update restart).
- `GET /api/update/check` → `{ok, current, latest, url, sha256, notes, available}` (reads `updates/payloads.json` from the repo raw URL, falls back to GitHub Releases `latest` API).
- `POST /api/update/apply` → downloads ELF to `/data/xeno-store/xeno-store.elf.new`, verifies sha256, renames to `xeno-store.elf`; `{ok, path, restartRequired:true}`.

### 6.2 Catalog
- `GET /catalog.json` → full catalog (not under /api; gzip + ETag).
- `GET /api/catalog/info` → `{ok, revision, generatedAt, games, releases, sources:[...], embeddedRevision, cachedRevision}`
- `POST /api/catalog/refresh` → `{ok, updated:bool, revision}` (blocking ≤ 60 s).
- `GET /api/catalog/search?q=&platform=&limit=` → server-side search (used by phone/desktop and as fallback): `{ok, items:[gameSummary...]}`.
- `POST /api/links/check {urls:[...]}` → HEAD/1-byte-range each (≤ 8, 10 s each) → `{ok, results:[{url, status, size, acceptRanges, finalUrl, ms}]}`.
- `POST /api/links/resolve {url}` → for known page hosts (dlpsgame post, archive.org item/details page) returns direct file links discovered server-side (`{ok, links:[{url,label,host,size?}]}`); for unknown hosts `{ok, links:[]}`.

### 6.3 Queue (downloads)
Job object:
```json
{"id":"j_1a2b3c","gameId":"cyberpunk-2077","title":"Cyberpunk 2077","titleId":"PPSA04029","platform":"PS5",
 "cover":"https://...","releaseId":"ppsa04029-ffpfsc","format":"FFPFSC","provider":"Archive.org","sourceId":"archive",
 "url":"https://...","mirrors":["https://..."],"filename":"PPSA04029 Cyberpunk 2077.ffpfsc",
 "root":"/data","rootLabel":"Internal","path":"/data/homebrew/PPSA04029 Cyberpunk 2077.ffpfsc",
 "state":"downloading","phase":"","message":"","error":"","errorCode":"",
 "total":156011528192,"written":12345678,"speed":52428800,"eta":2740,"connections":8,"segments":[[0,100,100],[100,200,50]],
 "sha256":"","sha256Expected":"","verified":false,"verify":"size"|"sha256"|"none",
 "addedAt":1760000000,"startedAt":0,"finishedAt":0,"attempts":1,"nextRetryAt":0,"priority":0,
 "autoInstall":true,"install":{"state":"idle"|"installing"|"installed"|"failed","message":"","contentId":""},
 "resumable":true,"etag":"","lastModified":""}
```
States: `queued` → `connecting` → `downloading` → `verifying` → `done`; side states `paused`, `failed`,
`cancelled`, `installing` (for PKG after done when autoInstall), `installed`. `phase` is free text for sub-steps.

- `GET /api/queue` → `{ok, jobs:[...], summary:{active, queued, paused, failed, done, speed, remaining, eta, keepAwake:bool}}`
- `POST /api/queue {gameId, releaseId, root, connections?, verify?, autoInstall?, url?}` →
  validates release exists (or accepts a raw `url` + `filename` + `format` for "Enter file link"), checks the
  destination (free space ≥ total + 256 MiB; not already queued; final file absent or `overwrite:true`),
  creates job → `{ok, job}`; errors: `no_space`, `exists`, `bad_release`, `root_unavailable`, `downloads_unavailable`.
- `POST /api/queue/{id}/pause|resume|cancel|retry|remove|restart|install|verify|move {direction:"up"|"down"|"top"|"bottom"}` → `{ok, job}`
  - `cancel`: stops, keeps the partial unless `{deleteFiles:true}`; state `cancelled`.
  - `remove`: forgets the entry; `{deleteFiles:true}` also deletes partial/final+sidecar (only job-owned paths).
  - `restart`: discard partial, requeue from zero.
  - `install`: start PKG install for a `done` package.
  - `verify`: compute sha256 (when expected is known) in background; sets `verified`.
- `POST /api/queue/clear {states:["done","cancelled","failed"]}` → `{ok, removed:n}` (keeps files).
- `GET /api/queue/{id}/log` → `{ok, lines:[...]}` per-job recent log.
- `POST /api/queue/{id}/url {url}` → replace the source URL (Enter file link / refreshed link) and resume; the partial is kept only when `total` matches the new response size.
- `GET /api/space?root=&bytes=` → `{ok, root, free, afterQueue, afterThis, fits:bool}` (queue = unfinished jobs on that root).

### 6.4 Storage & Library
- `GET /api/storage` → `{ok, roots:[{path:"/data",label:"Internal",kind:"internal"|"m2"|"usb",free,total,writable,default:bool}]}`
- `POST /api/storage/default {root}` → `{ok}`
- `GET /api/library?scan=1` → scans every root's `homebrew/`, `xeno-store/pkg/`, `xeno-store/files/` (depth ≤ 2) for
  `.exfat .ffpfsc .ffpkg .ffpfs .pkg .fpkg .zip .rar .7z .xpart` and `/user/app/<ID>` installed titles →
  `{ok, files:[{path,name,size,mtime,format,root,titleId?,gameId?,title?,cover?,partial:bool,jobId?}], installed:[{titleId,gameId?,title?,cover?,path}], scannedAt}`
  (matching by titleId regex `(PPSA|CUSA)\d{5}` in filename/path, then by normalized title).
- `POST /api/library/delete {path}` → only paths returned by the last scan (server keeps the allowlist); `{ok}`
- `POST /api/library/install {path}` → PKG install of a scanned .pkg; `{ok, job}` (creates a synthetic job in state `installing`).
- `POST /api/shadowmount/scan` → `POST http://127.0.0.1:10101/api/v1/scan` if ShadowMount answers; `{ok, available:bool, status}`.

### 6.5 Settings, favorites, collections, recent
- `GET /api/settings` → §9 object. `PUT /api/settings` (partial merge) → `{ok, settings}`.
- `GET /api/favorites` → `{ok, ids:[gameId...]}`; `PUT /api/favorites {ids}`; `POST /api/favorites/toggle {id}` → `{ok, favorite:bool}`
- `GET /api/collections` → `{ok, collections:[{id,name,icon,ids:[]}]}`; `PUT /api/collections` (whole list).
- `GET /api/recent` → `{ok, ids:[]}`; `POST /api/recent {id}` (keeps 30).
- `GET /api/export` → everything above in one JSON; `POST /api/import` restores.

### 6.6 Pairing
- `GET /api/pair` → `{ok, url:"http://192.168.1.20:9095/", ip, port, qr:"<svg string>"}` (server renders a simple QR as SVG using a tiny QR encoder in C? **No** — keep C small: the UI renders the QR with the vendored JS. The endpoint returns `url` only.)

## 7. Download engine behavior

### 7.1 Scheduling
- `settings.downloads.concurrentJobs` (1–4, default 1) jobs run at once, FIFO by `priority` then `addedAt`.
  Paused/failed don't occupy a slot. Move up/down reorders queued jobs.
- Each running job uses `connections` segments (1–16, default `settings.downloads.connections` = 8) **only if** the
  server answers a probe `GET` with `Range: bytes=0-0` → 206 + `Content-Range` total + (strong ETag or Last-Modified).
  Otherwise sequential single stream (still resumable by size when the server honors Range on resume).
- Segment plan: split total into chunks of max(16 MiB, total/connections) and assign dynamically from a
  shared "next chunk" cursor (work-stealing), so a slow connection doesn't stall the end.
  Per-origin adaptive window: start with `connections`, halve on 429/5xx/connection drop, grow by 1 every
  64 MiB of clean transfer (Overdrive idea).
- Buffers: 512 KiB per segment read; `pwrite` directly; `fsync` every 256 MiB and on pause/complete.
- Bandwidth limit: `settings.downloads.maxBytesPerSec` (0 = unlimited) via token bucket shared by all segments.
- Speed: EMA over 1 s samples; `eta = remaining / speed`. Summary speed = sum over jobs. Keep 60 samples per job for the UI sparkline (`speedHistory` array in `/api/queue` when `?history=1`).

### 7.2 Resume & sidecar
`<final>.xpart.json`:
```json
{"v":1,"url":"...","total":N,"etag":"...","lastModified":"...","chunk":16777216,"done":[[start,end],...],
 "written":N,"createdAt":t,"updatedAt":t,"sha256Expected":"","root":"/data","rootId":"dev:ino"}
```
Persist every 5 s and on every state change. On resume: re-probe; if `total` differs or validator (ETag /
Last-Modified) changed → state `failed` with `errorCode:"source_changed"` and message "The file on the server
changed. Restart from zero or pick another source." Never append to a mismatched partial.
Validator-less servers: resume by size only, and re-read the last 64 KiB of the partial against a Range
fetch of the same bytes before continuing (Overdrive's tail check).

### 7.3 Errors, retry, failover
- Transport error / 5xx / 429 → retry with backoff 5, 15, 45, 120, 300 s (max 8 attempts), honoring
  `Retry-After`. `nextRetryAt` is exposed so the UI shows a countdown.
- 401/403/404/410 on the primary URL → try the next entry in `mirrors` (same format & size from the catalog,
  ordered: verified direct > same provider > others) before failing. The job `message` says which mirror it switched to.
- A response with `Content-Type: text/html` (or a body starting with `<!DOCTYPE`/`<html`) when a file was expected
  → `errorCode:"provider_page"`: "The host returned a web page instead of the file. Open it in the browser or enter the direct file link."
- Disk full (`ENOSPC`) → `no_space`; drive gone (root `stat` fails) → `paused` with `drive_missing`.
- Free-space check before start and every 1 GiB.

### 7.4 Completion
1. If `sha256Expected` and `settings.downloads.verifyHashes` → `verifying` (stream the file; progress in `written`).
   Mismatch → `failed`/`hash_mismatch` (partial kept for inspection).
2. Rename `.xpart` → final, delete sidecar, `fsync` dir.
3. Toast "✓ <title> downloaded (<size>)" if `settings.notifications.toasts`.
4. If format is `pkg|fpkg` and (`job.autoInstall` or `settings.downloads.autoInstallPkg`) → §8.
5. If format is an image and `settings.downloads.shadowMountScan` → `POST /api/shadowmount/scan` best-effort.
6. `settings.downloads.keepAwake` tick stops when no job is downloading.

### 7.5 Queue persistence
`queue.json` = `{"v":1,"jobs":[...]}` written atomically on every state change and every 5 s during
transfers. On load: `downloading|connecting|verifying` → `paused` ("Stopped when XENO STORE closed");
`installing` → re-check install status once.

## 8. PKG install (install.c)

Primary: `sceAppInstUtilInitialize()` once, then `sceAppInstUtilInstallByPackage(&meta,&pkg_info,&playgo)` with
`meta.uri = "<absolute local path>"` (the ezremote-dpi / etaHEN DPI v2 recipe: a bare local path installs full
content; `AppInstallPkg` does NOT). Struct ABI exactly as `payload/dpi/sceAppInstUtil.h` in this repo
(copy the typedefs into install.c). Read the PKG header first: magic `7F 43 4E 54` ("\x7FCNT") at 0, content_id
36 bytes at offset 0x40 → `job.install.contentId`, title id = chars 7..15 of content_id. A PS5 fakepkg
(`\x7FFIH`) is accepted too (content id unknown → "").
Return 0 → `installing`; the housekeeping thread polls `/user/app/<TITLEID>` existence (+ optional
`sceAppInstUtilGetInstallStatus` if it resolves via dlsym) every 2 s for up to 30 min → `installed`
(toast "✓ <title> installed"). Non-zero → fallback chain:
1. DPI on `127.0.0.1:9040` (ezremote/XENO TOOL daemon): connect, send `<path>\n`, read decimal rc.
2. etaHEN DPI on `127.0.0.1:12800` (if present): same line protocol with `http://127.0.0.1:9095/pkgsrv/<token>`.
3. Give up → `install.state:"failed"` with the hex error and a hint ("Install it from XENO TOOL → Install, or etaHEN").
Host build: simulates success after 3 s (for UI tests).

### 10.1 Pipeline (`tools/catalog`)
- `sources/blackbox.py`: fetch `https://raw.githubusercontent.com/D3ATHLY/blackbox/main/catalog/{catalog,games,releases}.json`
  (fallback to `catalog/snapshots/blackbox/`). Maps PS5 (`PPSA`) and PS4 (`platform:"ps4"`, PKG) entries, keeps
  browserUrl for Vikingfile, verification info, genres, art (+fallbacks), region, version, consoleVerified.
- `sources/dlpsgame.py`: port of `client/src/lib/xenoStore.ts` (WordPress REST listing for PS5 + PS4 categories,
  cover from content, `fetchDownloadBundle` per post: titleId/region/version blocks with base/update/DLC mirrors, password,
  languages). Online only (403 to non-browser UA → send a real browser UA; respect 1 req/s). Snapshot fallback:
  `catalog/snapshots/xeno-dlpsgame/catalog.json` (name, platform, cover_url, page_url) → PAGE releases.
- `sources/archive_org.py` (online): `advancedsearch.php` for `PPSA* OR CUSA* OR ffpfsc OR exfat OR "ps4 fpkg"` across
  mediatype software/data, then `/metadata/<identifier>` → files with name/size/md5/sha1 → releases with
  `https://archive.org/download/<id>/<urlencoded name>`; titleId from filename/identifier regex; format from extension;
  version from `(\d+\.\d+(\.\d+)?)`; region from `[EU]/[US]/[JP]` or `EUR/USA/JPN` tokens.
- `sources/superpsx.py`, `sources/pkggames.py`, `sources/pspkg.py`, `sources/arabicps4.py`: best-effort ports (listing → PAGE releases + covers). Each wrapped in try/except with a per-source time budget.
- `merge.py`: normalize titles (strip ™®, editions, punctuation), group, pick best art (prosperopatches/orbispatches CDN first,
  then PlayStation CDN, then source cover), compute sizes/popularity/featured, assign genres, validate (every release
  has http(s) URL, size ≥ 0, platform ∈ PS4|PS5, no duplicate game ids), write compact JSON + `revision.json`
  (revision = previous + 1 when content changed, else unchanged) + `report.json` (counts per source, dropped reasons).
- `build_catalog.py --offline` must produce ≥ 1,900 games from the snapshots. `--online` is what the Action runs.

### 17.12 Full audit (`tools/catalog/audit.py`, run by the sync workflow and `make audit`)

### 17.14 Debrid / premium link support (faster than free hosts)
Settings → **Debrid**: connect one or more of **Real-Debrid**, **AllDebrid**, **TorBox**, **Premiumize** with the user's own API key
(stored only in `settings.json` on the console; shown masked). `GET /api/debrid` → `{ok, services:[{id,name,connected,user,expires,hosts:[...]}]}`,
`PUT /api/debrid {service, apiKey}` (validates with the service's user endpoint), `DELETE /api/debrid/{service}`.
Download options sheet gets **Download using**: Direct · <each connected service> · Auto (prefers a connected service when the host is supported).
Resolution (`debrid.c`): Real-Debrid `POST https://api.real-debrid.com/rest/1.0/unrestrict/link` (`Authorization: Bearer`, form `link=`) → `download`;
AllDebrid `GET https://api.alldebrid.com/v4/link/unlock?agent=xeno-store&apikey=&link=` → `data.link`; Premiumize `POST https://www.premiumize.me/api/transfer/directdl?apikey=` (`src=`) → `content[0].link`;
TorBox `POST https://api.torbox.app/v1/api/webdl/createwebdownload` (`link=`), poll `GET /v1/api/webdl/mylist?id=` until `download_finished`, then `GET /v1/api/webdl/requestdl?token=&web_id=&file_id=` → URL.
Supported-host lists are fetched once a day (`/hosts/domains`, `/v4/hosts`, `/api/services/list`) and cached. The unrestricted URL is downloaded with the normal segmented engine
(debrid CDNs support Range → up to 16 connections). Job shows `via Real-Debrid`. Errors map to plain words ("Real-Debrid says this host is not supported",
"Your TorBox plan limits files to 107 GB — pick a smaller format or download directly"). Keys never leave the console except to the chosen service.

### 17.15 Rest mode & background resilience
- XENO STORE is a daemon: closing the browser/TV app never stops downloads (already true).
- While anything downloads and `downloads.keepAwake` is on, `sceSystemServicePowerTick()` runs every 30 s so the console does not enter rest mode by itself.
- If the console does sleep (user action), sockets die: the housekeeping thread detects a monotonic-clock jump (> 10 s) or `ENETDOWN/ETIMEDOUT` bursts, marks
  affected jobs `connecting` (not failed), waits for the network (`getifaddrs` has a non-loopback address + a HEAD to the catalog revision URL succeeds), re-probes
  validators and resumes every segment exactly from its checkpoint. No retry budget is consumed by a sleep/wake cycle.
- Downloads screen shows a pill: "Console stays awake while downloading" / "Rest mode allowed — downloads resume on wake".

### 17.19 Engine notes learned from shipped PS5 homebrew (apply in `http_sce.c`, `zip.c`, `mdns.c`)
- Shipped payloads (ELF Arsenal, successor of Sonic Loader) use the **sceHttp v1 API** on PS5: `sceNetInit`, `sceNetPoolCreate`, `sceSslInit`,
  `sceHttpInit(net, ssl, 32K)`, `sceHttpCreateTemplate(ctx, ua, 2 /*HTTP/1.1*/, 1)`, `sceHttpSetResponseHeaderMaxSize(tmpl, 0x2000)`,
  `sceHttpsSetSslCallback(tmpl, cb_returning_0, NULL)` (accepts any certificate — use ONLY when `downloads.allowInsecureTls` or as an automatic retry after an
  SSL error, logged), `sceHttpCreateConnectionWithURL(tmpl, url, 0)`, `sceHttpCreateRequestWithURL(conn, 0 /*GET*/, url, 0)`, `sceHttpAddRequestHeader`,
  `sceHttpSendRequest`, `sceHttpGetStatusCode`, `sceHttpGetAllResponseHeaders`, `sceHttpGetResponseContentLength`, `sceHttpReadData`, `sceHttpAbortRequest`,
  `sceHttpSetRecvTimeOut/SetConnectTimeOut`, `sceHttpSetAutoRedirect`. `http_sce.c` implements **v1 first** (dlsym from `libSceHttp.sprx`/`libSceSsl.sprx`/
  `libSceNet.sprx`), with the Http2 symbols as a secondary backend when v1 is absent. One template per segment thread (contexts are not thread-safe across
  requests in flight); `sceHttpInit` once with a 2 MiB pool sized for 16 concurrent requests.
- **ZIP on the console**: vendor `miniz` (single header, MIT/unlicense — keep its header) under `src/third_party/miniz.h` and write `zip.c` (streaming
  reader with per-entry extraction to disk, 8 MiB buffers, path sanitization, size limits; writer for save backups). Enables: ZIP game archives extracted after
  download (into `<root>/homebrew/<name>/` for folder dumps or straight to the image file), save backups/restores, companion payload zips. RAR/7z stay download-only.
- **mDNS** (`mdns.c`, ~200 lines, no library): answer multicast DNS A queries for `xeno.local` and `xenostore.local` on 224.0.0.251:5353 with the console's IPv4
  (TTL 120), re-announce every 60 s. Pair-a-device shows `http://xeno.local:9095` next to the IP (phones/laptops on the same Wi-Fi resolve it). Opt-out in Settings.
- **Companion launch** stays "send bytes to the local ELF loader on :9021"; no in-process ELF loading.

### 17.22 PS5 Save Data Store (community saves, re-signed on the fly)
PS5 titles only (PPSA). Two entry points: a **Saves** tab on every PS5 game page ("Saves (n)" next to Download) and **Library → Community Saves** (browse all,
search, "My saves", "Upload my save"). Design: same cards/rails/sheets as the rest of the store; one primary gold action per screen.

**17.22.1 Data model** — `updates/saves.json` (published index; fetched like the catalog, cached 1 h; `settings.saves.indexUrls` may add more feeds):
```json
{"schemaVersion":1,"updatedAt":"…","saves":[{"id":"sv_…","titleId":"PPSA04029","gameId":"cyberpunk-2077-ps5","title":"Cyberpunk 2077",
 "category":"starter|platinum|checkpoint|modded|chapter|other","name":"Chapter 4 — all weapons unlocked","description":"…",
 "author":"nick","gameVersion":"01.004.000","region":"EUR","dirName":"SAVEDATA00","size":1234567,"sha256":"…","url":"https://pixeldrain.com/api/file/…",
 "mirror":"","format":"xeno-save-zip","createdAt":"…","downloads":0,"status":"published","tags":["ng+","max money"],"screenshot":""}]}
```
A **xeno-save-zip** = decrypted save files at the zip root + `xeno-save.json` manifest `{titleId, dirName, gameVersion, region, files:[{path,size,sha256}],
accountIdStripped:true, createdBy:"XENO STORE <ver>"}` + optional `sce_sys/param.sfo` with ACCOUNT_ID zeroed.

**17.22.2 Compatibility (safety net)** — for each save the UI computes: installed? (`/user/app/<titleId>`), installed version (read `/system_data/priv/appmeta/<titleId>/param.json`
→ `contentVersion`, falling back to `/user/app/<titleId>/sce_sys/param.json`), region match (exact titleId; other regions of the same game are listed under
"Other regions" with a warning: a save never loads on a different title ID), version compare (semantic): ✓ "Matches your 01.004.000", ⚠ "Made on 01.004.000, you have 01.000.000 —
update the game first (one-tap: opens the game's Updates)", ✗ "Game not installed". Incompatible saves are hidden by default (toggle "Show all"). CUSA→PPSA conversion is not
offered (there is no safe generic converter); the UI says so when a user looks for a PS4 save.

**17.22.3 Re-sign engine (`savemount.c`)** — three tiers, chosen automatically, reported honestly in the UI and `/api/saves/engine`:
1. **Native mount (preferred, needs kstuff-style save patches)**: PS5 SaveData API via dlsym from `libSceSaveData.sprx`: `sceSaveDataInitialize3(NULL)`,
   `sceSaveDataTransferringMount(userId, &titleId, &dirName, &fingerprint, &mountResult)` (mode RDWR | CREATE2 for imports), `sceSaveDataUmount`, `sceSaveDataDelete`,
   `sceSaveDataGetParam/SetParam` (title, subtitle, detail, user param) — the same calls the Apollo/Save-Mounter family uses. Import = create+mount a save for (current
   user, titleId, dirName) → copy files in → set `sce_sys/param.sfo` ACCOUNT_ID to the user's account id (offline-activated id from §17.18 when PSN is absent) → umount.
   Export = mount read-only → copy files out → strip ACCOUNT_ID (0) → zip + manifest. Every call's return code is logged; any failure aborts cleanly (umount, delete partial).
2. **Garlic Save Manager** (when `127.0.0.1:8082` answers): hand the zip path to its import/export endpoints; show "via Garlic".
3. **Raw copy** (same-console only): `/user/home/<uid>/savedata_prospero/<TITLEID>/` directory copy with automatic pre-backup; labelled "Same console only".
Host build simulates tier 1 (mounts = temp dirs) so the whole flow is testable in `tests/host/test_saves.py`.

**17.22.4 Install / download** — card actions: **Install to my saves** (download zip → verify sha256 → engine import → toast "Save installed — launch the game") with a
"Back up my current save first" checkbox (on); **Download file** (to `<defaultRoot>/xeno-store/saves/community/<title>/…zip`, reachable from PC via XENO TOOL/FTP);
**Report** (prefilled GitHub issue). Both go through the normal queue (job types `save-install`, `save-download`).

**17.22.5 Upload my save (one-click share)** — wizard: pick profile → pick PS5 title (installed titles with saves, auto-filled title + cover + installed version + region from the
catalog/appmeta) → pick the save dir → engine export (strips ACCOUNT_ID and console-specific signatures; never includes sealed keys) → zip + manifest → **upload** →
metadata form (category chips, name, description, tags, nickname; the game, version, region, size, sha256 are auto-filled) → **submit**.
- Upload adapters (`saveshare.c`, allowlisted hosts): **pixeldrain** (`PUT https://pixeldrain.com/api/file/<name>` → `{id}` → `https://pixeldrain.com/api/file/<id>`),
  **catbox** (`POST https://catbox.moe/user/api.php`, `reqtype=fileupload`, ≤ 200 MB), **custom** (`settings.saves.uploadEndpoint`, multipart `file` → `{url}`). Default: pixeldrain, fallback catbox.
- Submit adapters: **GitHub issue** (default, zero infrastructure): the console shows a QR + short URL to `https://github.com/XENOKING123/XENOKING/issues/new?template=save-submission.md&title=<…>&body=<json block>`
  so the user finishes on their phone; **custom** (`settings.saves.submitEndpoint`, `POST` JSON). The repo gets `.github/ISSUE_TEMPLATE/save-submission.md` and
  `.github/workflows/saves-intake.yml`: on issue opened/labeled, parse the JSON block, validate (URL reachable, size ≤ 2 GB, sha256 matches after download in CI, zip has
  `xeno-save.json`, titleId is PPSA, no sealed keys inside), append to `updates/saves.json` as `status:"pending"`; the owner adds label `approved` → status `published`
  (the Action rewrites the index and closes the issue; `rejected` label closes it without publishing). Consoles only show `published`.
- Privacy: no account ids, console ids or usernames leave the console; the nickname is typed by the user.

**17.22.6 Categories & browsing** — chips: Maxed Starter · 100% Platinum · Trophy checkpoint · Modded/Glitched · Chapter · Other; sort by newest/popular/version; search by
game/title ID/author; "Compatible with my games" quick filter (installed titles); per-game rail on the game page; Discover rail "New community saves".

**17.22.7 API** — `GET /api/saves/store?titleId=&category=&q=` (index + compatibility fields merged), `POST /api/saves/store/{id}/install {user, backupFirst}`,
`POST /api/saves/store/{id}/download`, `GET /api/saves/engine` → `{tier:"native"|"garlic"|"raw", detail}`, `POST /api/saves/export {user, titleId, dirName}` → zip path + manifest,
`POST /api/saves/upload {zipPath, host}` → `{url, sha256, size}`, `POST /api/saves/submit {…metadata}` → `{issueUrl, qr}`, `GET /api/saves/installed-version?titleId=`.

**17.22.8 Backends (the store talks to a real community database when one is configured)**
- **Supabase backend (preferred, owner-deployed)** — the schema the owner already has (`public.ps5_save_collection`: `id uuid, title_id PPSA#####, game, shared_by, notes,
  file_path, file_name, file_size, cover_path, garlic_id, created_at`; bucket `ps5-saves`; edge function `garlic-savedb` with actions list / download / sync / debug that
  mirrors garlicsaves.com's Save DB every 6 h). XENO STORE ships the deployable backend under `xeno-store/backend/supabase/`:
  `migrations/0000…0003` (as provided) + `0004_xeno_save_store.sql` (adds `category text`, `game_version text`, `region text`, `tags text[]`, `downloads int default 0`,
  `status text default 'published'`, `source text default 'xeno'`, an RPC `increment_downloads(id)`, and an index on `(title_id, created_at desc)`),
  `functions/garlic-savedb/index.ts` (ported with XENO naming; secrets `GARLIC_SAVEDB_SESSION`, `GARLIC_SAVEDB_CF`, optional username/password stay server-side),
  `functions/xeno-save-submit/index.ts` (validates an insert: PPSA id, sizes, zip contains no sealed keys when the file is in our bucket) and a README with the exact
  deploy steps. The console never sees Garlic cookies.
  Runtime config: `updates/saves-backend.json` → `{"kind":"supabase","url":"https://<ref>.supabase.co","anonKey":"<public anon key>","bucket":"ps5-saves","garlicFunction":"garlic-savedb"}`
  (fetched with the catalog; overridable in Settings → Saves → Backend). The anon key is public by design (RLS); writes are limited by the table's policies.
  Payload adapter (`savestore_supabase.c`): list `GET {url}/rest/v1/ps5_save_collection?select=*&order=created_at.desc&limit=2000` (+ `&title_id=eq.PPSA…`) with
  `apikey` + `Authorization: Bearer <anon>`; covers via `POST {url}/storage/v1/object/sign/ps5-saves/<path>` (signed URL, 1 h, cached); download: storage rows via a signed URL,
  `garlic:<id>` rows via `POST {url}/functions/v1/garlic-savedb {"action":"download","id":N}` (streamed to the queue like any download); upload:
  `POST {url}/storage/v1/object/ps5-saves/<PPSA>/<uuid>-<name>.zip` (`Content-Type: application/zip`), cover `…-cover.png` extracted from the zip's `icon0.png`,
  then `POST {url}/rest/v1/ps5_save_collection` (`Prefer: return=representation`). Download counts via the RPC.
- **GitHub index backend** (zero infrastructure) — `updates/saves.json` + issue intake as in §17.22.5; used when no Supabase config is present. Both can be active (merged list,
  deduped by sha256/garlic_id).
- **Garlic compatibility** — Garlic's "decrypted save zip" (plaintext files + `sce_sys/icon0.png`, `param.sfo`) is accepted as-is by the install path (manifest optional:
  titleId comes from the index row, version/region from the row when present, else "unknown — check before installing"). Our uploads use the same layout plus `xeno-save.json`,
  so XENO saves work in Garlic and Apollo-style tools too.
- UI: store cards show cover (icon0 from the zip, else catalog art), game, title ID, category chip (from `category`, else inferred from notes keywords: "100%/platinum" →
  platinum, "start/ng+/max" → starter, "trophy/boss" → checkpoint, "mod/glitch" → modded), description, shared_by, date, size, downloads, compatibility badge. Upload dialog
  mirrors the owner's "Add PS5 save" form (title ID auto-filled, game, your name, description ≤ 300 chars, category, optional picture) but the zip comes from the engine export.
